# 17 · Harness Engineering（智能体运行壳工程）

> 横向工程能力之一。模型是"大脑"，**harness 是身体与环境**——包住 LLM 的那层
> 确定性代码：控制循环、工具运行时、文件系统、错误恢复、预算与停止条件、观测钩子。
> Claude Code / Cursor / Devin / SWE-agent 的本质都是 harness。建议在 `11` 之后、
> `13` 之前穿插，它把 `01` 的玩具 loop 升级成能干活的运行时。

## 学习目标

- 看清 agent = 模型 + **harness**，能力上限常常卡在 harness 而非模型
- 掌握 **Agent–Computer Interface（ACI）**：把工具接口当"给模型用的 UI"来设计
- 把 `01` 的裸 loop 升级为有预算/超时/防循环/可重放的**生产级控制循环**
- 设计工具运行时：沙箱、并发、超时、可重试、危险动作审批
- 用文件系统/环境作外部状态，配合 `16` 做上下文卸载
- 在 harness 里埋观测钩子（为 `12` 服务），支持 replay 调试

## 核心概念

### 1. 什么是 harness
- 模型只会"输出 token"；让它**真正改变世界**的是外面这层代码
- harness = 控制循环 + 工具执行 + 环境/IO + 状态 + 错误处理 + 观测
- **关键认知**：同一个模型，harness 不同，能力天差地别（SWE-bench 分数差几倍）

### 2. Agent–Computer Interface（ACI）⭐ 核心洞见
- 工具/动作接口要**为模型设计**，像给人设计 UI 一样反复打磨
- SWE-agent 的发现：把"编辑文件/跑测试"的接口做得对模型友好，分数大涨
- 设计要点：动作粒度合适、反馈即时可读、错误信息**可操作**（让模型能自纠）
- 逐条自检见 `02` 的 **工具设计 rubric（ACI 自检表）**

### 3. 控制循环工程（深化 `01`）
- **停止条件**：任务完成 / 超 max_steps / 超预算（token、时间、$）
- **防失控**：超时、限流、熔断
- **防循环**：检测"重复同一动作/在原地打转"，强制换策略或中止
- 预算感知：把剩余预算告诉模型，让它合理收尾

### 4. 工具执行运行时
- **沙箱**（呼应 `11`）：隔离危险操作、限制文件/网络/资源
- 并发与超时：一轮多工具并行（呼应 `02`）、每个工具独立超时
- 幂等与重试：可安全重试的工具标注幂等；副作用工具要小心
- **危险动作审批**（呼应 `13` HITL）：付款/删数据/发消息前停下等人

### 5. 工具结果处理（与 `16` 协同）
- 截断 / 分页 / 格式化 / 降噪——**决定喂回多少**，直接影响上下文与成本
- 错误回填要"可操作"：不是抛 stacktrace，而是"哪错了、可以怎么改"

### 6. 文件系统 / 环境作为状态
- 别把一切塞上下文：用文件 / DB / 工作区作**外部状态**（呼应 `16` 写出）
- **code-as-action（CodeAct）**：让模型用写代码代替逐个 JSON 工具调用，
  表达力更强、步数更少（适合 code agent，呼应 `11`）

### 7. 错误恢复与韧性
- 重试 / 回滚 / 断点续跑（呼应 `13` 持久化）
- 部分失败处理：一个工具挂了不拖垮整轮
- 把失败变成 observation 喂回，给模型自我纠正的机会（呼应 `01`/`06`）

### 8. 观测钩子与可重放
- 在 harness 里埋 trace / log / metric（为 `12` eval & tracing 铺路）
- **replay**：存下每步 messages + 工具 IO，能离线重放复现 bug——调 agent 的命根子

### 9. 确定性脚手架 vs 模型自主
- **能写死的别交给模型**：固定流程用代码，只把真需要判断的留给 LLM
- "12-Factor Agents"的核心主张：把 agent 当软件工程，而非"全靠模型聪明"

### 10. 案例拆解
- 读 **SWE-agent** 的 ACI、**smolagents** 的 loop、**Claude Code** 的工具集设计，
  对照你自己的 harness 找差距

### 11. 状态模型：5 种状态各放哪 ⭐
harness 要分清自己在管哪种状态，别混成一锅（呼应 `03`/`16`/`18`）：

| 状态 | 是什么 | 放哪 | 生命周期 |
|---|---|---|---|
| `messages` | 当前对话 / 工作记忆 | 模型上下文 | 单次运行（会被裁剪 / 压缩） |
| `runtime_context` | 用户、权限、环境、配置 | 进程 / 请求作用域 | 单次运行，**不进**模型上下文 |
| `store` | 跨会话长期记忆 | DB / 向量库 | 持久（呼应 `03`/`04`） |
| `scratchpad` / 文件系统 | 长程任务外置状态 | 文件 / 工作区 | 任务级（呼应 `16` 写出） |
| `trace` / replay | 调试与评估状态 | 日志 / jsonl | 离线（呼应 `12` 与 §8） |

> 混淆这几类是 bug 与越权的常见来源：别把含权限的 `runtime_context` 塞进模型上下文，
> 也别把该持久化的 `store` 只放在易丢的 `messages` 里。

4. [ ] 加 **replay 日志**：每步存 messages + 工具 IO，写一个离线重放器复现一次 bug

## 完成标准

- [ ] 你的 agent loop 有预算/超时/防循环，不会失控烧钱
- [ ] 至少一个工具是"为模型设计"的（错误信息可操作、结果分页）
- [ ] 能用 replay 日志离线复现并定位一次 agent 出错
- [ ] 能讲清"harness 决定能力上限"，并说出 ACI 是什么
- [ ] 理解"能写死就别交给模型"的工程取舍
